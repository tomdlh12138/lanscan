# LAN Scan（Web 版）· 局域网设备扫描

一个**纯前端**的局域网设备扫描器，专为 **iPad Safari** 设计——无需 Mac、无需编译、无需服务器后端。把三个文件丢到任意能访问的地方，用 iPad 的 Safari 打开即可扫描同 Wi‑Fi 下的设备。

> 这是原 iPadOS 原生 App（Swift + Network 框架）方案在「没有 Mac 无法编译」情况下的替代实现。**浏览器能力远弱于原生 App**，详见下方「能力边界」。

## 文件结构

```
LANScan-Web/
├── index.html                     界面结构
├── styles.css                     iPad 适配深色主题样式
├── app.js                         扫描引擎（端口探测 + 并发 + 结果渲染）
├── README.md                      本说明
└── .github/workflows/deploy.yml   GitHub Pages 一键部署配置
```

## 怎么用（三种打开方式，任选其一）

### 方式 A：部署到静态托管（最推荐，最省事）
把这三个文件上传到任意静态托管（GitHub Pages / Vercel / Netlify / 自己的 Nginx），得到一个 `https://xxx` 链接。iPad Safari 打开该链接即可。

> 用 `https` 托管的页面在探测 `http://` 局域网设备时会触发「混合内容」限制，浏览器可能**拦截 http 请求**。若发现探测全部失败，请改用方式 B（同网段 http 托管）或把页面也以 `http` 提供。

### 方式 A-2：用 GitHub Pages 一键部署（配置文件已附）

本仓库已包含 `.github/workflows/deploy.yml`。把它推到 GitHub 即可自动发布：

1. 在 GitHub 新建仓库，把 `LANScan-Web/` 里的**全部内容（含 `.github/`）直接放到仓库根**（即仓库根应有 `index.html` 与 `.github/` 同级）。
   - 注意：GitHub 只识别**仓库根**的 `.github/`，别把它留在子目录里，否则 Actions 不会触发。
   - 默认 `path: '.'` 即部署仓库根内容；若你确实把文件放在仓库根的 `LANScan-Web/` 子目录，再把 `path` 改为 `'LANScan-Web'`。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**。
3. 推送到 `main`（或 `master`）分支，Actions 会自动构建并发布；也可在 Actions 页手动 Run。
4. 发布完成后拿到 `https://<用户名>.github.io/<仓库名>/`，iPad Safari 打开即用。

> ⚠️ **混合内容提醒**：GitHub Pages 是 `https`，页面去探测 `http://` 局域网设备时，Safari 可能因「混合内容」拦截 http 请求，导致全部探测失败。遇到这种情况二选一：
> - 改用 **方式 B**（同网段 `python3 -m http.server`，以 `http` 提供页面，避免混合内容）；或
> - 只探测 `https` 端口（自签名证书仍会被拦，见能力边界）。

### 方式 B：本机起一个本地服务器（适合临时用）
在一台和 iPad **同一 Wi‑Fi** 的电脑上：

```bash
cd LANScan-Web
python3 -m http.server 8080
```

然后查这台电脑的局域网 IP（如 `192.168.1.20`），在 iPad Safari 打开：

```
http://192.168.1.20:8080/
```

### 方式 C：直接打开文件
用 iPad 的「文件」App 打开 `index.html`。部分情况下 `file://` 协议会限制跨协议 `fetch`，若探测失败请改用方式 A/B。

## 使用步骤

1. 连上要扫描的 Wi‑Fi（iPad 与目标设备同一局域网）。
2. 点 **「自动检测本机网段」** 自动填入（Safari 可能隐藏本机 IP，填不上就手动选快捷网段或输入前缀，如 `192.168.1`）。
3. 选好要探测的端口（默认勾选 9 个 HTTP/HTTPS 端口，SSH/SMB 等纯 TCP 端口默认不勾且标注「不可靠」）。
4. 点 **「开始扫描」**，结果实时出现在右侧卡片；点卡片看详情、可一键打开设备 Web 管理页。
5. 扫完点 **「导出 CSV」** 保存结果。

## 可调参数

界面上所有关键参数都可调，无需改代码：

| 参数 | 位置 | 默认值 | 说明 |
|------|------|--------|------|
| 网段前缀 / 主机范围 | 顶部输入框 + 快捷按钮 | `192.168.1.1~254` | 指定要扫描的 IP 区间，支持任意 /24 段 |
| 探测端口 | 端口区勾选 / 自定义添加 | 9 个 HTTP/HTTPS 端口 | 纯 TCP 端口（SSH/SMB…）默认不勾且标注「不可靠」 |
| 并发数 | 输入框 | `30` | 同时进行的探测请求数，范围 1–100，建议 20–40 |
| 超时(ms) | 输入框 | `1200` | 单个 IP:端口 的等待上限，范围 300–5000；网络慢可调大 |

> 调大「超时」能提高对响应慢的设备（如部分摄像头、NAS）的发现率，但会拖长整体扫描时间；调大「并发」能加快扫描，但过高可能触发 Safari 每主机连接上限或路由器限流。

## 实现原理

- **本机网段**：通过 WebRTC 的 ICE candidate 尽力提取私有 IP（Safari/iOS 可能返回 mDNS 混淆地址 `.local`，此时需手动输入）。
- **设备发现**：对「网段 × 端口」逐个发起 `fetch(http(s)://IP:PORT, {mode:'no-cors'})`，用 `AbortController` 超时（默认 1200ms）+ 错误判定：
  - 请求成功（拿到 opaque 响应）→ 该端口有 HTTP(S) 服务在响应 → 视为发现设备；
  - 超时 / 连接被拒 / 协议不匹配 → 视为该端口关闭。
- **并发**：固定大小并发池（默认 30），避免压垮 Safari 的每主机连接上限。
- **标题获取**：对开放端口再尝试一次 `cors` 请求解析 `<title>`，多数设备禁用跨域，通常拿不到（best‑effort）。

## 能力边界（务必了解）

浏览器沙箱决定了它**做不到原生 App 的程度**，已尽量如实标注：

| 能做到 | 做不到 / 会误判 |
|--------|----------------|
| 发现开放 **HTTP/HTTPS** 端口的设备（路由器、摄像头、NAS、智能家居网关、打印机 Web 页、开发服务器等） | 发 ICMP ping、做原始 TCP、读 MAC 地址 / 厂商 |
| 列出设备开放的应用层端口与协议 | **自签名证书的 HTTPS 设备**（证书校验失败 → 误判为关闭） |
| 尽力获取本机网段 | **SSH/SMB/FTP 等纯 TCP 端口**（浏览器无法识别，默认不勾，勾了也会误判关闭） |
| 实时卡片 + 详情 + CSV 导出 | mDNS/Bonjour 服务发现（浏览器无 mDNS API） |

**一句话总结**：Web 版最擅长发现「带 Web 管理界面的局域网设备」，对只有命令行服务（SSH/SMB）或无 Web 界面的设备无能为力。若需要更完整的发现能力，仍建议找一台 Mac 编译原生版。

## 隐私

纯前端实现，所有扫描均在你的浏览器内完成，**不向任何第三方服务器发送数据**，结果只存在本机内存（刷新即清空，不写入磁盘）。

## 与原生版（Swift）的差异

| 维度 | 原生版（Swift / Network 框架） | Web 版（本仓库） |
|------|------------------------------|------------------|
| 发现机制 | Bonjour/mDNS + TCP 端口探测 | HTTP(S) 端口探测 |
| 能发现 SSH/SMB 设备 | ✅ | ❌（浏览器限制） |
| 能发现自签名 HTTPS | ✅ | ❌（证书校验） |
| 读 MAC / 厂商 | ❌（iOS 隐私限制） | ❌ |
| 是否需要 Mac 编译 | 需要 | 不需要 |
| 运行环境 | iPad App | iPad Safari（任意浏览器） |
